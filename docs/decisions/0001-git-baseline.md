# ADR-0001：仓库 Git 基线与首次提交说明

- 状态：已接受
- 日期：2026-08-27
- 决策者：开发者
- 相关文档：P0 执行计划 §11.1、README §30

## 背景

P0 执行计划 §11.1 建议先单独提交 Product Definition v0.1 基线，再审查、暂存并提交 README v0.2 与执行计划，使分阶段演进在 Git 历史中清晰可追溯。

实际执行时，本地工作区同时存在已暂存的 v0.1 文件（.gitattributes、.gitignore、README.md 初版）以及工作区中尚未提交的 v0.2 改动与 docs/product/P0_EXECUTION_PLAN.md。建立 GitHub 仓库时，这三部分被一次性暂存并合并为单个 initial commit（含 4 文件、1739 行），随后推送到 origin/main。

## 决策

不回退已推送的历史。以本 ADR 记录以下事实，作为基线说明：

1. initial commit（949afcc）一次性纳入了 v0.1 文件、v0.2 改动和 P0 执行计划，并已推送到 origin/main；
2. 此后阶段 0 的每一组文档以独立 commit 逐步加入，遵循执行计划 §21 的推荐提交序列精神；
3. 本 ADR 之后的文档提交使用 docs: 前缀，实现类提交使用 feat:/test:/build: 前缀。

## 后果

- Git 历史中 v0.1 与 v0.2 不再分离到不同 commit，但内容完整、可追溯；
- 不影响阶段 0 的文档门槛与一致性审查：后续文档以本 commit 之后的代码状态为基线；
- 任何引用 v0.1 基线 commit 的检查改为引用 949afcc，并以本文作为差异说明。

## 备注

该处理方式已与开发者确认。阶段 0 文档门槛（执行计划 §11.3）仍需逐项通过后才允许阶段 1 开始。
