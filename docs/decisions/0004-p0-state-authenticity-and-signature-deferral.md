# ADR-0004：P0 状态真实性与签名后置决策

- 状态：已接受
- 日期：2026-08-27
- 决策者：开发者
- 相关文档：执行计划 §8.2、ADR-0002、安全不变式 INV-4

## 背景

执行计划 §8.2 要求阶段 0 用 ADR 回答 P0 快照真实性使用 AEAD、MAC 还是签名，P0 是否需要设备签名，以及不得仅为未来 P1 预留而引入没有当前验证价值的密钥角色。

执行计划 §3.3 指出 P0 单快照阶段不引入未定义的 mutable head，只有在 localhost HTTP 或 P1-alpha 需要表达最新状态、前驱和条件更新时才通过正式状态协议定义 head。

## 决策

### P0 不引入设备签名

P0 不实现设备身份签名和可变 Domain State 签名。理由：

1. P0 是单用户、单设备、单快照场景，没有多设备或多成员需要验证彼此身份；
2. 设备签名在 P0 中没有当前验证价值：没有第二台设备需要验证签名，没有服务端需要验证客户端身份；
3. 仅为 P1 预留而引入设备签名密钥会增加密钥图复杂性，违反最小密钥角色原则（执行计划 §8.2）。

### 真实性通过 AEAD 提供

P0 快照真实性使用 AEAD（认证加密），不使用独立 MAC 或签名：

- 密文对象和 Manifest 敏感字段使用 AEAD 加密，机密性和完整性一体提供；
- 篡改通过 AEAD 解密失败检测，恢复验证失败关闭（满足 INV-4、INV-14）；
- 不需要独立的签名验证步骤或签名密钥管理。

### ObjectStore 不含 head

P0 单快照阶段不引入 mutable head 指针。ObjectStore 只保存不可变对象，不表达"最新状态"或"前驱关系"。

原因：

- P0 没有增量同步、多快照或状态分叉，不需要前驱关系；
- 在没有增量状态语义时引入 head 会产生未定义的状态协议，违反诚实原则；
- localhost HTTP 或 P1-alpha 需要表达最新状态时，再通过正式状态协议定义 head、前驱和条件更新。

### P0 状态名复用但不等价生产状态

P0 复用 README §8 的状态名（LocalPrepared → RecoverySetupPending → PossessionVerified → Active），但：

- P0 的 Active 只表示允许创建 P0 加密快照，不表示真实多设备同步启用；
- P0 不产生可变 Domain State：快照是不可变的，不存在状态分叉或前驱链；
- P0 的状态转换是本地门槛，不经服务端串行确认。

## 后果

- P0 密钥图不含设备签名密钥（见 ADR-0002）；
- P0 Manifest 不含签名字段，只用 AEAD 认证；
- P1-alpha 迁移时需要：引入设备签名密钥对、定义可变 Domain State 和前驱链、定义 head 语义和条件更新协议；
- P1-alpha 的设备签名引入不能破坏当前恢复根→域数据根的派生链和 AEAD 认证模型。

## 硬停止条件

如果阶段 6 破坏性测试发现 P0 篡改/真实性测试确实需要设备签名（即 AEAD 不足以检测某些篡改场景），必须回到本 ADR 修改决策后才能引入签名，不能静默在实现中加入签名。
