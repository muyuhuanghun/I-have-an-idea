- 状态：**草案（分析材料已备）—— 三项确认点待开发者回答后接受；在裁决前 DP-016 保持 `deferred`，不承诺任何部署形态**

- 决策者：开发者（OWNER-PRODUCT）
- 相关文档：DP-016/DP-017（账号认证）、ADR-0024（localhost HTTP ObjectStore）、ADR-0026（状态协议）、执行计划 §18/§24、README 设备信任模型

## 1. 背景与现状

P0/P1-alpha 已落地的部署事实：ObjectStore 与 head 目录都在**本机磁盘**（Directory 后端 + head 目录），Stage 7 另交付了 localhost HTTP 传输（服务器 + 客户端适配器），head 链（指针 + 设备注册 + 分叉检测）已在本地目录实现。三种候选模式的裁决决定：head 指针与对象存储的托管拓扑、多设备支持的引入时点、以及 DP-017（账号认证）的先后。

## 2. 三模式对比（迁移/运维成本表）

| 维度 | 设备本地（现状） | 自托管 | 中心托管 |
| --- | --- | --- | --- |
| 形态 | store + head 目录在本机磁盘 | 用户自跑内网/ localhost 服务器（Stage 7 传输 + head 指针网络端点） | 运营方服务器托管 store、head 与账号 |
| 迁移成本 | 零（已实现） | 中：head 指针网络化端点（新合同）+ 服务器运维文档 | 高：账号体系（DP-017 前置）、TLS 传输合同（当前 localhost 明文不够）、滥用防护、删除 SLA（DP-021 联动）、运营方可见性声明 |
| 运维成本 | 零 | 用户自担（一台常驻机器） | 运营方持续承担 |
| 安全边界 | 环境访问控制；head 链签名 + 本地 journal | 同左 + 内网传输；token 进程本地 | 需账号授权（DP-017）、传输加密、服务端防篡改 |
| 多设备 | 不支持（每设备独立 head 链） | 支持（分叉检测已就绪，冲突走用户裁决） | 支持 |
| 依赖 | 无 | Stage 7 传输（已交付） | DP-017 + TLS 合同 + DP-021 |
| 开源/信任 | 完全本地，无第三方可见性 | 第三方=用户自己 | 运营方可见密文元数据（键/大小/时序） |

## 3. 裁决内容（待确认）

> 裁决尚未作出（2026-09-05 本轮仅交付分析材料）。三条确认点均推荐按"推荐"选项接受：并行模式 / 以本 ADR 关闭 DP-016 / 指针网络化列 P1-beta。

1. **并行模式**：P1-alpha/P1-beta 以**设备本地为默认形态**（已实现、零迁移），**自托管**作为进阶路径（复用 Stage 7 HTTP 传输；head 指针网络化端点列为 P1-beta 合同清单），**中心托管推迟到 P1-release** 且以 DP-017（账号）+ TLS 传输合同 + DP-021（删除 SLA）为前置。三种模式共存于路线图，任何时点切换都不要求改动 core（ObjectStore/head 端口边界已验证）。
2. **DP-016 关闭**：本 ADR 即 close_artifact 要求的"deployment ADR"；迁移/运维成本表见 §2。部署形态承诺自接受起受本 ADR 约束，后续改变需新合同。
3. **指针网络化排期**：head 指针/设备注册的网络端点列入 P1-beta 合同清单（P1-alpha 不实现），并以 DP-017 的账号裁决为前置。

## 4. 待开发者确认的三个确认点

1. **模式裁决**：并行模式（推荐——设备本地默认 + 自托管进阶 + 中心托管后置）；或中心托管优先（需先完成 DP-017）；或自托管优先。
2. **DP-016 关闭**：以本 ADR 关闭 DP-016（planning 完成，实现合同另立）（推荐）；或保持 deferred 至自托管实现落地。
3. **指针网络化排期**：列入 P1-beta（推荐）；或 P1-alpha 立即实现。

## 5. 后果

- 接受后新增 wire token `P1_DEPLOYMENT_MODE_RULING_ACCEPTED`；DP-016 状态按确认点 2 裁决；DP-017 保持 `deferred`（中心托管前置）。
- 本 ADR 不授权任何实现；自托管 head 指针网络端点、账号体系均需后续合同。
- 不承诺：多设备并发写一致性（分叉显式检测不变）、跨部署形态迁移工具（迁移兼容性承诺需新合同）。
