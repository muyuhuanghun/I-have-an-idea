# ADR-0029：P1 账号生命周期设计（DP-017 设计合同）

- 状态：**已接受（2026-09-08 开发者确认三项推荐选项；DP-017 设计合同已关闭；不实现真实账号）**
- 日期：2026-09-08
- 草案阶段：P1-alpha account design（DP-017）
- 决策者：开发者（OWNER-PRODUCT）
- 相关文档：DP-017、ADR-0028（部署模式裁决：并行模式，中心托管推迟到 P1-release 且本设计为其前置）、DP-021（删除 SLA）、ADR-0026（状态协议：devices.json 设备注册）、README 设备信任模型

## 1. 背景与边界

ADR-0028 裁决并行模式：设备本地为默认（无账号），中心托管推迟到 P1-release 且以本设计（DP-017）为前置。本 ADR 冻结账号体系的**模型方向与硬边界**——它约束未来实现合同的形状，但不是实现授权；真实账号实现（含服务端）需在 P1-release 前另立合同。

## 2. 设计冻结（方向与边界）

1. **账号 = 托管层身份，不参与端到端信任**：账号存在仅为中心托管模式的服务编排（对象存储配额、head 指针托管、设备注册代理）；E2EE 信任根仍是设备密钥与 head 链签名（ADR-0026），账号凭据泄露**不等于**域密钥泄露。
2. **认证方向（已接受）**：Passkey 优先（WebAuthn，无密码库、防钓鱼、天然双因子：绑定设备 + 生物/PIN）；一次性恢复码仅作为账号登录和托管层会话的兜底，不作为设备信任或域访问授权；密码+TOTP 不作为本设计的默认认证基础。
3. **恢复硬边界（冻结为 INV-19 候选；本轮不写入或翻转正式 registry）**：**账号恢复 ≠ 域密钥恢复**。一次性恢复码只能恢复账号登录/托管层会话，不能单独授权向 E2EE `devices` registry 写入，也不能授予 `head` 签名权。新设备加入 trusted devices 必须由既有已授权设备签名批准；未来如需域恢复，只能另立不改变既有信任承诺的用户自持域恢复合同。若全部可信设备与域恢复材料均丢失，账号恢复码不能恢复域访问或设备信任。任何"服务器恢复域"的宣称都被本设计禁止。
4. **删除语义（与 DP-021 联动）**：账号删除 = 托管层删除（账号元数据 + 托管密文对象按 DP-021 SLA 清除）；客户端本地副本与用户自持密钥不在服务器能力范围内——删除声明必须限定为"托管层删除"。设备在删除前导出 head 链与恢复材料后可离线继续。
5. **滥用/恢复威胁 delta（DP-017 close_artifact 的具体化；本轮不翻转 THR-06/07）**：新增威胁候选——THR-06（恶意批量注册与资源滥用：缓解方向 = 创建质询/限流）、THR-07（恢复流程钓鱼：缓解方向 = 账号登录恢复仅允许用户在可信官方入口主动提交一次性恢复码，服务器不发送“点此恢复”式凭据收集链接；E2EE 设备信任恢复仍仅由既有已授权设备端内签名批准，恢复码不得授权 devices/head）。该 delta 作为未来 P1-release 实现合同的输入，不等于本轮已有正式威胁 registry 项。
6. **与状态协议的衔接**：devices.json 的远期演进 = 托管设备注册表的服务端镜像（账号绑定设备列表）；本设计不改变 ADR-0026 的本地 devices.json 语义。

## 3. 裁决记录（2026-09-08，开发者确认）

> 三项确认点已按推荐选项接受。本次接受只关闭 DP-017 的设计合同，不授权真实账号、服务端、Passkey/WebAuthn 或网页控制台实现，也不新增或翻转 THR-06、THR-07、INV-19 或任何 ACC。

1. **认证方向已接受**：Passkey 优先 + 一次性恢复码兜底；不把密码库或密码+TOTP 作为默认认证基础。
2. **恢复边界已接受**：冻结“账号恢复 ≠ 域密钥恢复”为 INV-19 候选；一次性恢复码只恢复账号登录/托管层会话，不能单独写入 E2EE `devices` registry 或授予 `head` 签名权。新设备必须由既有已授权设备签名批准；若全部可信设备与域恢复材料丢失，恢复码不能恢复域访问或设备信任。未来用户自持域恢复若要引入，必须另立且不得改变既有信任承诺的合同。本轮不把 INV-19 写入或翻转正式 registry。
3. **DP-017 已关闭**：本 ADR 作为设计 closeout；真实账号和中心托管服务仍需在 P1-release 前另立实现合同，并在该合同中重新定义正式威胁、不变式、验收项和证据门。

## 4. 后果

- 接受后新增 wire token `P1_ACCOUNT_LIFECYCLE_DESIGN_ACCEPTED`；DP-017 按本 ADR 关闭；DP-021（删除 SLA）保持 `deferred` 并新增"托管层删除"联动注记。
- 一次性恢复码只恢复账号登录/托管层会话；它不能单独授权写入 E2EE `devices` registry，也不能授予 `head` 签名权。新设备信任仍须既有已授权设备签名批准，未来用户自持域恢复必须另立合同；若全部可信设备与域恢复材料丢失，恢复码不能恢复域访问或设备信任。
- 本 ADR 不授权任何实现；中心托管的服务端实现合同在 P1-release 前起草，届时必须重新落实 §2.5 的 THR-06/07 威胁定义与正式 registry 变更。
- 设备本地默认形态（ADR-0028）不受影响：无账号路径继续零依赖可用。
- 简单网页控制台仍未立项；本阶段收尾后另行确认其范围、身份边界和是否起草独立合同，不因本 ADR 获得实现授权。
