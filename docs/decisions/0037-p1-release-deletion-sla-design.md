# ADR-0037：P1-release 主存储与备份物理删除 SLA 设计（DP-021）

- 状态：**已接受（2026-09-12）——开发者委托裁决（"继续 P1-release 设计族"），采纳推荐选项并经四视角两轮自检；可事后否决，否决即回滚关闭状态**
- 日期：2026-09-12
- 决策者：开发者（OWNER-PRODUCT 归属；委托按推荐路径裁决）
- 阶段：P1-release deletion design（DP-021 关闭切片，纯设计；"deletion SLA/ADR + provider evidence" 落为 SLA 定义 + 验收证据计划，实现与正式证据随发布工程切片另授权）
- 相关文档：DP-021、ADR-0005/0006（Recovery File 与域密钥模型）、ADR-0028（部署模式）、ADR-0033（epoch 边界）、crypto-shredding/NIST SP 800-88 调研（2026-09-12）

## 1. 问题与范围

"删除"在本产品里必须精确到存储层级与承诺强度：主存储（本地 Vault 外的 ObjectStore/head/登记物）、设备本地副本、自托管共享存储、以及用户自行制作的第三方备份。hard stop：关闭前不得承诺物理删除时限——本设计给出可承诺的精确 SLA 并显式划定不承诺的部分。

## 2. 行业先例（调研 2026-09-12）

| 先例 | 机制 | 启示 |
| --- | --- | --- |
| Crypto-shredding / NIST SP 800-88 | 销毁密钥使密文永久不可解，无需触碰所有副本 | E2EE 产品的删除承诺根基是密钥销毁，不是介质擦除 |
| AWS KMS cryptographic erasure | KMS 密钥删除后备份中的数据不可解 | 备份无需逐份擦除，密钥生命周期即删除生命周期 |
| SLA 对齐研究 | **密钥库备份保留窗必须短于承诺的擦除 SLA**，否则密钥从备份复活、承诺失效 | SLA 是一条时序约束，不只是"删了" |

## 3. 裁决一：删除的语义分层——密码学擦除为承诺根基

1. **L-主存储**（本地 ObjectStore/head 目录/登记物/快照日志）：删除 = 授权流程移除文件与目录（常规文件系统删除），并销毁域密钥本地副本。密文残余（SSD wear-leveling 等不可控因素）因密钥销毁而**不可解**——安全承诺的根基是密钥销毁，不是介质擦除（NIST 800-88 clear + cryptographic erase 级别）。
2. **L-设备本地副本**：Vault 本体（用户的明文）永远归用户所有，产品**从不**触碰 Vault（既有硬边界延续）；"删除域"只删除产品管理的密文侧材料，Vault 明文的处置是用户自己的动作。
3. **L-自托管共享存储**：管理员经显式流程删除域对象；副本策略（若有）必须文档化且保留窗短于 SLA（§4）。
4. **L-第三方备份**：用户自行制作的备份（网盘/外置盘）不在承诺范围——文档必须明示，E2EE 语义下这些备份在密钥销毁后同样不可解（这正是产品架构给用户的天然保障，但作为陈述而非承诺）。

## 4. 裁决二：精确 SLA（v1 冻结数值与时序）

| 承诺 | 范围 | 时限 | 依据 |
| --- | --- | --- | --- |
| 主存储删除完成 | 本地 ObjectStore/head/登记物/日志（产品管理的全部密文侧文件） | 删除命令执行**即时**完成，命令返回即承诺达成 | 本地文件删除 + 目录移除 |
| 域密钥销毁完成 | 本地密钥副本 + Recovery File 由用户自毁（产品给出指引） | 产品侧密钥副本即时；用户持有份额的销毁是用户动作 | 密码学擦除模型 |
| 自托管共享存储删除 | 服务端域对象 | 管理员执行**即时**；服务端备份/副本保留窗 **≤ 7 天**且必须文档化 | SLA 对齐研究：密钥/对象备份保留窗必须短于承诺时限 |
| 云托管形态 | **不适用** | ADR-0028 裁决云托管留 P1-release 之后，本 SLA 不对不存在形态承诺 | 并行模式 |

1. 密钥库/对象备份保留窗（7 天）**必须短于**任何对外声称的擦除时限——若未来对外承诺"30 天擦除"，7 天窗满足时序约束（先例：一个月承诺 + 七天密钥备份 = 设计成立）。
2. 物理扇区级擦除（purge 级）**不承诺**：SSD wear-leveling 使逐扇区承诺不可验证；安全声明锚定在"密文不可解"而非"字节不存在"。

## 5. 裁决三：删除的授权与不可逆语义

1. 删除域 = 所有者设备授权操作（复用既有登记权威语义）；删除前必须通过**显式确认交互**（输入域 ID 或确认短语），防误触。
2. 删除不可逆：删除后恢复只能靠删除前导出的备份/Recovery File；产品文档不得暗示"可撤销的删除"。
3. 删除事件入审计（追加式记录：何时、谁、哪个域——不含被删内容任何信息）。

## 6. 验收证据计划（设计级，"provider evidence" 随发布工程切片落库执行）

| # | 场景 | 期望 |
| --- | --- | --- |
| DS-1 | 授权删除后扫描产品管理的全部密文侧路径 | 路径不存在/对象计数为零，命令返回即时 |
| DS-2 | 删除后以 Recovery File 尝试恢复 | 失败关闭（密钥副本已销毁；用户自留备份的行为属用户域） |
| DS-3 | 删除事件审计 | 追加式记录在场，不含被删内容信息 |
| DS-4 | 文档与 UI 文案扫描 | 无物理扇区擦除承诺、无第三方备份承诺、无云托管 SLA 越级表述 |
| DS-5 | 自托管形态删除 + 副本保留窗 | 管理员删除即时；副本窗配置 ≤ 7 天且已文档化 |

## 7. 候选 registry delta（随发布工程切片落库）

候选威胁 **DEL-THR-01** 删除被表述为跨层承诺（越级）；**DEL-THR-02** 密钥库备份窗长于 SLA；**DEL-THR-03** 未授权删除。候选不变式 **DEL-INV-01** 删除承诺只覆盖产品管理的存储；**DEL-INV-02** 密钥销毁是删除承诺的根基；**DEL-INV-03** 删除需显式确认且入审计；**DEL-INV-04** 副本保留窗 ≤ 承诺时限。候选 ACC 对应 DS-1..5。

## 8. 诚实边界

1. 不承诺物理扇区擦除；安全根基 = E2EE 密文 + 密钥销毁。
2. 不承诺第三方备份的删除；E2EE 使其在密钥销毁后不可解是架构陈述。
3. 云托管 SLA 留白至该形态真正引入（另立裁决）。
4. 实现与正式证据随发布工程切片另授权；本 ADR 关闭不产出任何代码。

## 9. 自检记录（四视角两轮，2026-09-12）

**第一轮**：管理者——SLA 数值（7 天副本窗）首次成文，运营文档需引用（修订：§4.2 注明）；用户——Vault 明文永不触碰的边界重申（§3.2 已有）；部署——设备本地与自托管两形态分层覆盖，云留白（§4 表）；安全——最大风险 = 越级承诺（DEL-THR-01/DS-4 文案扫描防守）+ 备份窗时序（DEL-THR-02/§4.2 数值防守）。**第二轮**：hard stop 对齐（本关闭即解除"不得承诺物理删除时限"，但只允许承诺 §4 表所列精确内容 ✓）；DS-1..5 覆盖三裁决 ✓；与 ADR-0028/0033 无冲突 ✓。结论：可关闭 DP-021。
