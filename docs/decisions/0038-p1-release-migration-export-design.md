# ADR-0038：P1-release 自托管迁移与密文导出格式设计（DP-022）

- 状态：**已接受（2026-09-12）——开发者委托裁决（"继续 P1-release 设计族"），采纳推荐选项并经四视角两轮自检；可事后否决，否决即回滚关闭状态**
- 日期：2026-09-12
- 决策者：开发者（OWNER-PRODUCT 归属；委托按推荐路径裁决）
- 阶段：P1-release portability（DP-022 关闭切片，纯设计；"versioned export format ADR + roundtrip migration evidence" 落为格式冻结 + 验收证据计划，实现与正式证据随发布工程切片另授权）
- 相关文档：DP-022、ADR-0015（Directory ObjectStore 可移植先例）、ADR-0026/0027（head 链验证原语）、ADR-0032/0033（团队登记物）、ADR-0037（删除 SLA，迁移的源退役联动）

## 1. 问题与范围

自托管迁移 = 把一个域的全部**密文侧状态**从一处（本地目录/自托管 A）搬到另一处（自托管 B/新机器），且**迁移器永不接触明文**（E2EE 语义下迁移器无解密路径）。hard stop：关闭前不得承诺无损自托管迁移——本设计以"字节级往返"兑现无损承诺并冻结版本化导出格式。

## 2. 设计基础（全部为仓库既有原语，零新密码学）

| 既有原语 | 在迁移中的角色 |
| --- | --- |
| DirectoryObjectStoreV1（扁平目录，文件名 = canonical key） | 密文对象原样拷贝（自包含、可移植，ADR-0015 先例） |
| head 目录（签名指针 + history journal + devices.json） | 状态权威随域整体迁移，导入后用既有验证原语复验 |
| 登记物（proposal-reviewers / group-state / epoch-keys，ADR-0035） | 团队状态随域迁移（含恢复锚公钥；**锚私钥材料不迁移**） |
| Recovery File | 不进导出包——迁移后内容可读性由既有成员本地密钥保证；Recovery File 的新副本发放是用户独立动作 |
| build-meta / schema 版本 | 版本兼容判定的输入 |

## 3. 裁决一：版本化导出格式 `ekd-domain-export-v1`

1. 导出包 = 一个**目录形态捆绑**（可整体压缩传输）：
   ```
   ekd-domain-export-v1/
     manifest.json                  // 版本、域 ID sha、生成时间、源形态、
                                    // objects[]: {key, sha256, size}、
                                    // head_files[]: {name, sha256}、
                                    // registries[]: {name, sha256}、generator_commit
     objects/<canonical-key>        // 密文对象，原样字节
     head/                          // head 目录文件原样（指针/journal/devices.json）
     registries/                    // proposal-reviewers/group-state/epoch-keys 原样
   ```
2. manifest 是完整性的根：列出的每个文件都有 sha256，导入验证 = 逐文件哈希比对 + 清单自身与源 commit 绑定。
3. **密文自包含原则**：导出包不含任何密钥材料（内容密钥/私钥/恢复材料）——迁移器只搬运密文与公钥事实；目标侧可读性由成员既有本地密钥 + head 链验证保证。这使"迁移器零明文接触"成为结构性性质而非流程承诺。
4. 向前兼容规则：未来 `v2` 格式必须能读 `v1` 包（v1 清单字段为 v2 子集）；导入器遇到更高版本必须失败关闭并如实提示，不得猜测。

## 4. 裁决二：迁移流程与无损承诺

1. **导出**（源侧，源继续服务读取）：权威设备执行，生成捆绑包 + manifest；导出不改动源任何状态（只读遍历）。
2. **导入**（目标侧）：逐文件哈希比对 → head 链验证（既有原语：指针签名/设备注册/序列单调）→ 登记物签名验证 → 幂等落盘（已存在且哈希一致的对象跳过——中断后重跑安全）→ 完成后目标侧输出验证报告。
3. **无损承诺的精确定义**：roundtrip 后，目标侧每个对象的字节与源一致（清单哈希全等）+ head 链在目标侧验证通过 + 登记物签名验证通过。**不承诺**：迁移过程中的新增快照（源需在导出窗口只读或接受增量再导出）；成员本地密钥的迁移（那些从来不在服务器上）。
4. **切换窗口**：建议流程 = 源设为只读 → 导出 → 导入验证 → 目标服务 → 源退役（删除遵循 ADR-0037 SLA）。产品不做自动切换，迁移工具输出核对清单。

## 5. 验收证据计划（设计级，"roundtrip migration evidence" 随发布工程切片落库执行）

| # | 场景 | 期望 |
| --- | --- | --- |
| MG-1 | 完整 roundtrip（本地 A → 捆绑 → 本地 B） | 逐对象 sha256 与 manifest 全等；head 链在 B 侧验证通过 |
| MG-2 | 导入后既有语义复验 | head 读最新验证通过；登记物签名验证通过；团队 epoch 状态可加载 |
| MG-3 | 迁移器零明文接触 | 迁移实现无 CryptoProvider/解密调用（代码审查断言）+ 产物扫描无私钥/明文标记 |
| MG-4 | 中断恢复 | 部分导入后重跑：已存在且哈希一致的对象跳过，最终全等 |
| MG-5 | 版本不匹配 | manifest 版本高于导入器 → 失败关闭并如实提示 |
| MG-6 | 篡改检测 | 捆绑中任一文件字节被改 → 哈希比对失败关闭 |
| MG-7 | 导出只读性 | 导出前后源侧全部文件哈希不变 |

## 6. 候选 registry delta（随发布工程切片落库）

候选威胁 **MIG-THR-01** 捆绑篡改/部分替换；**MIG-THR-02** 版本降级攻击（旧导出回灌）；**MIG-THR-03** 迁移器被实现为解密器。候选不变式 **MIG-INV-01** 迁移器零明文接触；**MIG-INV-02** manifest 哈希闭环；**MIG-INV-03** 导入幂等；**MIG-INV-04** head 序号不降。候选 ACC 对应 MG-1..7。

## 7. 诚实边界

1. 无损承诺 = 密文侧字节往返；成员本地明文/密钥不在迁移范围（它们本来就不在服务器上）。
2. 迁移窗口内的新快照不自动增量（流程建议只读窗口；增量迁移为未来能力）。
3. 跨版本 schema 演进（head/登记物未来升版）的兼容矩阵在实现合同冻结；v1 只承诺 v1 → v1。
4. 实现与正式证据随发布工程切片另授权；本 ADR 关闭不产出任何代码。

## 8. 自检记录（四视角两轮，2026-09-12）

**第一轮**：管理者——迁移是运维动作，核对清单（§4.4）给流程锚点；密钥不迁移的语义需要向用户讲清（修订：§3.3 明示"目标侧可读性由成员本地密钥保证"）；用户——导出/导入各一条命令的形态（实现合同冻结命令面）；部署——目录形态捆绑对自托管最友好（可 rsync/压缩），对象存储后端形态留未来；安全——迁移器零明文是结构性性质（§3.3），零解密调用断言入 MG-3。**第二轮**：hard stop 对齐（本关闭解除"不得承诺无损自托管迁移"，承诺精确为 §4.3 字节级往返 ✓）；MG-1..7 覆盖三裁决 ✓；与 ADR-0015/0026/0032/0033/0037 无冲突 ✓。结论：可关闭 DP-022。
