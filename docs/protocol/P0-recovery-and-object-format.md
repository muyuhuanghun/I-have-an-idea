# P0 恢复文件与对象 ID 格式要求

> 文档版本：v0.2
> 状态：阶段 0 工作单元 8
> 日期：2026-08-27
> 权威来源：README §8、执行计划 §8.3-8.4、ADR-0002

## 1. 职责

冻结 P0 恢复文件和密文对象的确定性版本化格式要求。实现前必须关闭本文档列出的全部参数；实现阶段不得偏离已冻结格式。格式变更需要 ADR 并提升版本号，不能静默修改。

## 2. 恢复文件格式

### 2.1 必须包含的字段

| 字段 | 说明 | 是否敏感 |
|---|---|---|
| Magic | 固定魔数，标识文件类型 | 否 |
| 格式版本 | 恢复文件结构版本号 | 否 |
| 协议版本 | 加密协议版本号 | 否 |
| 域 ID（Domain ID） | 不透明域标识 | 否（不透明） |
| 密码套件标识 | 标识使用的 AEAD、KDF、nonce 方案 | 否 |
| 恢复材料 | 恢复根（Recovery Root）的受保护形式 | 是（高敏感） |
| 完整性信息 | 防止恢复文件被篡改（HMAC 或 AEAD 标签） | 是 |
| 非秘密指纹 | 用于用户识别恢复文件对应哪个域，不含秘密 | 否 |
| Manifest 定位符 | 指向 ObjectStore 中的 Manifest 对象 ID | 否（不透明） |

### 2.2 Manifest 定位符的恢复链作用

Manifest 定位符是闭合 fresh-process 恢复链的关键字段：

```text
fresh-process 恢复链：
  1. 新进程读取 Vault 外恢复文件
  2. 验证完整性（HMAC 或 AEAD 标签）
  3. 提取恢复根 → 派生域数据根（HKDF）
  4. 读取 Manifest 定位符 → 从 ObjectStore 获取 Manifest 密文对象 ID
  5. 从 ObjectStore GET 该对象 ID → 获得 Manifest 密文
  6. 用 Manifest 密钥（从域数据根派生）解密 Manifest → 获得文件条目和包装的对象密钥
  7. 逐条解包对象密钥 → 从 ObjectStore GET 密文对象 → AEAD 解密 → 写入新建空目录
  8. Python 独立验证器逐文件核对相对路径和字节
```

没有 Manifest 定位符，fresh-process 不知道从 ObjectStore 的哪个对象 ID 读取 Manifest，恢复链在第 4 步断裂。Manifest 定位符本身是 ObjectStore 中的不透明对象 ID，不含明文信息，可安全存入恢复文件。

### 2.3 恢复文件禁止包含

- 原 Vault 绝对路径；
- 任何笔记正文、文件名或扩展名；
- 账号密码或其他认证秘密；
- 明文恢复根（恢复根必须受完整性保护，不能裸存为可读字节）。

### 2.4 恢复根保护方式

恢复根在恢复文件中以受保护形式存储，不以明文字节裸存：

- 恢复根由 CSPRNG 生成，位数不低于 256 位（32 字节）；
- 恢复根经完整性封装后写入恢复文件的"恢复材料"字段（具体方案：AEAD 封装或 HMAC + 加密，在参数冻结时确定）；
- 完整性信息字段验证恢复材料未被篡改或替换；
- 生成后关闭写入句柄并重新从磁盘读取，验证完整性校验通过；
- 恢复文件被视为足以恢复域的高敏感秘密，P0 不提供远程备份或托管。

恢复根失窃等价于获得域解密能力。恢复文件丢失或失窃等价于域被攻破。

### 2.5 生成与验证流程

1. 恢复根由 CSPRNG 生成，位数不低于 256 位（32 字节）；
2. 从恢复根派生域数据根（HKDF）；
3. 从域数据根派生 Manifest 密钥；
4. 加密 Manifest 并写入 ObjectStore，获得 Manifest 对象 ID；
5. 恢复文件按格式版本写入磁盘，包含恢复根（受保护）、Manifest 定位符（Manifest 对象 ID）和其他字段；
6. 生成后关闭写入句柄；
7. 重新从磁盘读取恢复文件，解析并验证完整性；
8. 持有性验证：新进程重新读取恢复文件，通过 Manifest 定位符从 ObjectStore 获取 Manifest 并恢复（满足 INV-10）；
9. 仅依赖勾选框、内存中尚未清除的密钥或源进程状态均不合格。

## 3. 密文对象格式

### 3.1 对象结构

每个密文对象是不可变字节序列，按以下逻辑结构组织（具体字节布局在实现时冻结）：

```text
[格式版本] [协议版本] [密码套件标识]
[nonce / IV]
[AEAD 加密的明文 + 认证标签]
```

Manifest 对象和文件密文对象使用相同的对象格式。Manifest 定位符就是 Manifest 对象的对象 ID。

### 3.2 对象 ID

对象 ID 是 ObjectStore 中标识密文对象的键。要求：

| 参数 | 要求 | 待冻结值 |
|---|---|---|
| 随机位数 | 不低于 128 位，碰撞概率在 P0 规模（10,000 对象）下可忽略 | smoke test 后冻结 |
| CSPRNG 来源 | 通过 RandomSource 端口获取，不依赖 Math.random | 候选见 smoke test 方案 |
| 编码 | URL-safe Base64 或 Hex，不带语义前缀 | 实现时冻结 |
| 碰撞检查 | 生成后检查 ObjectStore 是否已存在同 ID，碰撞则重新生成 | 实现时验证 |
| 与域绑定 | 对象 ID 不含域 ID 前缀；域归属通过 Manifest 表达 | 是 |
| 认证附加数据 | 对象类型、版本等元数据作为 AEAD 的 AAD | 实现时冻结 |

### 3.3 禁止裸内容哈希作为对象 ID

对象 ID 不得是文件内容的哈希。裸内容哈希会泄漏内容关系：攻击者可通过相同对象 ID 推断两个文件内容相同（满足 INV-3）。对象 ID 必须是随机不透明标识。Manifest 对象 ID 同样随机生成，不含内容语义。

### 3.4 相同明文不可关联

相同明文重复加密不得产生可直接关联的相同密文对象（满足 INV-2）。原因：

- 每对象密钥独立随机生成（ADR-0002）；
- 每对象 nonce 独立随机生成；
- 对象 ID 随机生成，不含内容哈希。

## 4. 重放边界

P0 单快照阶段的重放边界定义如下：

### 4.1 P0 不存在跨快照重放

P0 只验证单个快照的创建和恢复。不涉及增量同步、多快照历史或状态分叉，因此不存在跨快照的重放风险（如旧快照对象被重放到新状态）。

### 4.2 P0 单快照内的重放保护

在单快照恢复过程中：

- ObjectStore 对象是不可变的，恢复器按 Manifest 中的对象引用逐个 GET；
- 同一对象 ID 被多次 GET 返回相同密文是预期行为（幂等），不构成重放攻击；
- 恢复器验证每个对象的 AEAD 标签，篡改或替换的对象会被检测（满足 INV-4）；
- 恢复器拒绝重复的对象 ID 引用（同一对象 ID 在 Manifest 中出现多次导致路径冲突），防止通过对象引用重放导致覆盖。

### 4.3 阶段 7 及以后的重放边界

localhost HTTP ObjectStore（阶段 7）引入网络后，重放边界扩展为：

- 幂等重试：同一 PUT 请求重传应幂等，不产生重复对象；
- 条件更新：阶段 7 定义最新状态指针和条件更新后，旧状态对象不应被重放到新状态（需状态序号或加密代际验证）；
- P0 不提前引入这些机制，在阶段 7 通过正式状态协议定义。

## 5. 版本化策略

### 5.1 格式版本

恢复文件、密文对象和 Manifest 各有独立的格式版本号。版本号是单调递增整数。恢复器必须拒绝不支持的格式版本（满足 INV-14）。

### 5.2 协议版本

协议版本标识加密套件和密钥派生方案。协议版本变更等价于新密码代际，旧恢复文件可能无法用新协议恢复（旧代际停止用于新状态）。

## 6. 实现前必须冻结的参数清单

以下参数在密码候选 smoke test（阶段 1）完成后、阶段 2 实现开始前必须冻结：

- 恢复根位数（不低于 256 位）；
- KDF 参数（HKDF 的 salt、info、输出长度）；
- 对象密钥包装方案（AES-KW 或 AEAD 封装）；
- 恢复根保护方案（AEAD 封装或 HMAC + 加密）；
- 恢复文件完整性方案（HMAC 或 AEAD 标签）；
- 对象 ID 随机位数（不低于 128 位）和编码；
- nonce 位数和生成策略；
- AEAD 具体算法（XChaCha20-Poly1305 或 AES-256-GCM）；
- AAD 的具体字段和编码；
- Manifest 定位符的具体编码（与对象 ID 编码一致）。

冻结后写入补充 ADR，并在恢复文件和对象格式中固定版本号。
