# P0 恢复文件与对象 ID 格式要求

> 文档版本：v0.1
> 状态：阶段 0 工作单元 8
> 日期：2026-08-27
> 权威来源：README §8、执行计划 §8.3-8.4、ADR-0002

## 1. 职责

冻结 P0 恢复文件和密文对象的确定性版本化格式要求。实现前必须关闭本文档列出的全部参数；实现阶段不得偏离已冻结格式。格式变更需要 ADR 并提升版本号，不能静默修改。

## 2. 恢复文件格式

### 2.1 必须包含的字段

| 字段 | 说明 | 是否敏感 |
|---|---|---|
| Magic | 固定魔数，标识文件类型 | 否 |
| 格式版本 | 恢复文件结构版本号 | 否 |
| 协议版本 | 加密协议版本号 | 否 |
| 域 ID（Domain ID） | 不透明域标识 | 否（不透明） |
| 密码套件标识 | 标识使用的 AEAD、KDF、nonce 方案 | 否 |
| 恢复材料 | 恢复根（Recovery Root）或其受保护形式 | 是（高敏感） |
| 完整性信息 | 防止恢复文件被篡改 | 是 |
| 非秘密指纹 | 用于用户识别恢复文件对应哪个域，不含秘密 | 否 |

### 2.2 恢复文件禁止包含

- 原 Vault 绝对路径；
- 任何笔记正文、文件名或扩展名；
- 账号密码或其他认证秘密；
- 明文恢复根（恢复根必须受完整性保护，不能裸存为可读字节）。

### 2.3 生成与验证流程

1. 恢复根由 CSPRNG 生成，位数不低于 256 位（32 字节）；
2. 恢复文件按格式版本写入磁盘；
3. 生成后关闭写入句柄；
4. 重新从磁盘读取恢复文件，解析并验证完整性；
5. 持有性验证：新进程重新读取恢复文件，证明可凭 Vault 外材料恢复（满足 INV-10）；
6. 仅依赖勾选框、内存中尚未清除的密钥或源进程状态均不合格。

### 2.4 恢复文件视为高敏感秘密

恢复文件足以恢复域，等同于域根密钥。恢复文件丢失或失窃等价于域被攻破。P0 不提供恢复文件的远程备份或托管。

## 3. 密文对象格式

### 3.1 对象结构

每个密文对象是不可变字节序列，按以下逻辑结构组织（具体字节布局在实现时冻结）：

```text
[格式版本] [协议版本] [密码套件标识]
[nonce / IV]
[AEAD 加密的明文 + 认证标签]
```

### 3.2 对象 ID

对象 ID 是 ObjectStore 中标识密文对象的键。要求：

| 参数 | 要求 | 待冻结值 |
|---|---|---|
| 随机位数 | 不低于 128 位，碰撞概率在 P0 规模（10,000 对象）下可忽略 | smoke test 后冻结 |
| CSPRNG 来源 | 通过 RandomSource 端口获取，不依赖 Math.random | 候选见 smoke test 方案 |
| 编码 | URL-safe Base64 或 Hex，不带语义前缀 | 实现时冻结 |
| 碰撞检查 | 生成后检查 ObjectStore 是否已存在同 ID，碰撞则重新生成 | 实现时验证 |
| 与域绑定 | 对象 ID 不含域 ID 前缀；域归属通过 Manifest 表达 | 是 |
| 认证附加数据 | 对象类型、版本等元数据作为 AEAD 的 AAD | 实现时冻结 |

### 3.3 禁止裸内容哈希作为对象 ID

对象 ID 不得是文件内容的哈希。裸内容哈希会泄漏内容关系：攻击者可通过相同对象 ID 推断两个文件内容相同（满足 INV-3）。对象 ID 必须是随机不透明标识。

### 3.4 相同明文不可关联

相同明文重复加密不得产生可直接关联的相同密文对象（满足 INV-2）。原因：

- 每对象密钥独立随机生成（ADR-0002）；
- 每对象 nonce 独立随机生成；
- 对象 ID 随机生成，不含内容哈希。

## 4. 版本化策略

### 4.1 格式版本

恢复文件、密文对象和 Manifest 各有独立的格式版本号。版本号是单调递增整数。恢复器必须拒绝不支持的格式版本（满足 INV-14）。

### 4.2 协议版本

协议版本标识加密套件和密钥派生方案。协议版本变更等价于新密码代际，旧恢复文件可能无法用新协议恢复（旧代际停止用于新状态）。

## 5. 实现前必须冻结的参数清单

以下参数在密码候选 smoke test（阶段 1）完成后、阶段 2 实现开始前必须冻结：

- 恢复根位数（不低于 256 位）；
- KDF 参数（HKDF 的 salt、info、输出长度）；
- 对象密钥包装方案（AES-KW 或 AEAD 封装）；
- 恢复文件完整性方案（HMAC 或 AEAD）；
- 对象 ID 随机位数（不低于 128 位）和编码；
- nonce 位数和生成策略；
- AEAD 具体算法（XChaCha20-Poly1305 或 AES-256-GCM）；
- AAD 的具体字段和编码。

冻结后写入补充 ADR，并在恢复文件和对象格式中固定版本号。
