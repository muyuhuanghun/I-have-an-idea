# P0 安全不变式与服务器元数据边界

> 文档版本：v0.2
> 状态：安全不变式草案；Phase 0 复审门禁重新打开
> 日期：2026-08-27
> 权威来源：README §5、§28、执行计划 §6

## 1. 职责

冻结 P0 的安全不变式和服务器元数据边界。这些不变式是 P0 实现的硬约束：任何测试或实现违反它们时，必须停止当前阶段并记录负面证据，不能带病进入下一阶段。

## 2. 安全不变式

### 2.1 加密不变式

| 编号 | 不变式 | 说明 |
|---|---|---|
| INV-1 | 正文、文件名、扩展名、路径结构、内部链接和本地修改时间在离开设备前加密 | 服务器只能看到不透明密文 |
| INV-2 | 相同明文重复加密不得产生可直接关联的相同密文对象 | 每对象独立随机密钥和 nonce |
| INV-3 | 对象 ID 是随机不透明标识，禁止裸内容哈希 | 防止内容关系泄漏 |
| INV-4 | 密文对象使用认证加密（AEAD），篡改必须被检测 | 恢复验证逐文件核对字节 |
| INV-5 | 域根密钥和可恢复明文的秘密材料只在授权设备产生和使用 | 服务端不得生成域根密钥 |

### 2.2 路径不变式

| 编号 | 不变式 | 说明 |
|---|---|---|
| INV-6 | 路径必须始终保持在指定 Vault 根目录内 | 不允许扫描或恢复路径逃出根目录 |
| INV-7 | Symlink、Junction 和重解析点被拒绝 | 不跟随、不上传、不恢复 |
| INV-8 | 恢复目标必须是新建空目录 | 非空目标目录被拒绝 |
| INV-9 | 源 Vault 在扫描和同步过程中零写入 | 扫描器不在源 Vault 创建缓存、数据库或临时文件 |

### 2.3 恢复不变式

| 编号 | 不变式 | 说明 |
|---|---|---|
| INV-10 | 持有性验证必须重新读取保存在 Vault 外的恢复文件 | 仅依赖勾选框、内存密钥或源进程状态不合格 |
| INV-11 | fresh-process 恢复只凭恢复文件和 ObjectStore | 不得依赖未声明的本地缓存或内存秘密 |
| INV-12 | 恢复成功必须由独立验证器逐文件核对相对路径和字节 | Python 验证器独立于加密核心 |
| INV-13 | 任何部分写入不能被报告为完整成功 | 恢复是原子验证 |

### 2.4 完整性不变式

| 编号 | 不变式 | 说明 |
|---|---|---|
| INV-14 | 恢复器必须拒绝非空目标、路径逃逸、大小写折叠碰撞、缺失/截断/篡改对象、错误恢复文件和不支持的格式版本 | 失败关闭 |
| INV-15 | 扫描中变化的文件不得进入伪一致快照 | 文件读取前后检查变化 |
| INV-16 | 未支持文件不被静默跳过 | 返回 UnsupportedFilesFound 并阻止快照完成 |

上述完整性不变式只约束“给定快照”的内部认证、恢复和失败关闭。P0 没有外部 freshness anchor、可信计数器或最新状态指针，因此不能检测一套合法旧恢复文件与匹配旧 ObjectStore 的整体替换；这不是 INV-14 已经覆盖的能力。

## 3. 服务器元数据边界

### 3.1 P0 允许 ObjectStore 观察的元数据

以下元数据在 P0 中是 README §5.2 长期元数据边界的严格子集：

- 不透明域 ID；
- 不透明对象 ID；
- 对象数量；
- 每个密文对象大小；
- 总密文字节数；
- 上传和下载时间；
- 协议版本。

P0 不定义 mutable `head`、状态序号或加密代际；若后续状态协议引入这些字段，必须另行更新本边界和验收。

P0 不做大小填充、对象数量隐藏或流量隐藏，必须在关闭报告中记录该限制。

### 3.2 P0 不允许 ObjectStore 观察的元数据

- 正文；
- 原始文件名；
- 扩展名；
- 相对路径；
- Markdown 链接；
- Canvas 内容；
- 裸内容哈希；
- 密钥和恢复秘密；
- 账号 ID、成员 ID、权限事件和配额事件（P0 不产生这些控制面字段）。

### 3.3 服务器可见性验证

关闭报告中必须包含服务器可见性扫描结果：在 ObjectStore 存储和日志中扫描测试预置的明文标记，证明上述禁止信息不出现。任何禁止的明文信息出现在 ObjectStore 或日志中是硬停止条件。

## 4. AI 边界（P0 运行时零 AI）

P0 运行时不得包含 AI 组件。AI 只允许用于开发辅助、测试数据生成或离线分析报告，不能参与：

- 随机数或密钥生成；
- 加密或完整性判断；
- 路径验证；
- 域激活；
- 恢复成功判定；
- 权限和安全不变式判断。

## 5. 硬停止条件

发生以下任一情况必须停止当前阶段，不得带病进入下一阶段：

- 任何测试修改了源 Vault；
- fresh-process 恢复依赖未声明的本地缓存或内存秘密；
- ObjectStore 或日志出现禁止的明文信息；
- 共享核心必须导入 Node/Electron 才能工作；
- 10,000 文件处理仍按 Vault 总大小无界占用内存；
- 未支持文件被静默遗漏；
- 路径验证允许写出目标根目录；
- 篡改或错误密钥被当成成功。

停止后只做问题定位、范围修订和负面证据记录，不继续后续功能。

## 6. 声明诚实边界

P0 关闭报告不得宣称：

- "已经实现零知识安全"；
- "已 GDPR 合规"；
- "已通过独立审计"；
- "已达到生产可用状态"。
- “已证明当前输入是历史最新快照”或“已提供完整快照反回滚”。

这些声明需要实现、测试和独立审计证据支持，不属于 P0 范围。负面结果和被排除的能力必须明确记录，不用宣传语言掩盖。
