# P0 威胁模型

> 文档版本：v0.2
> 状态：诚实回滚边界已形成；恢复文件/Manifest/对象认证绑定仍待关闭
> 日期：2026-08-27
> 权威来源：README §5.3、§23、执行计划 §6

## 1. 职责

识别 P0 范围内的资产、攻击者和信任边界。本文件不覆盖 P1 及以后的团队、成员和正式域主恢复威胁。P0 的安全目标是证明本地加密快照闭环的完整性，不证明零知识安全或合规。

## 2. P0 范围声明

P0 只验证以下闭环：在 Windows 上选择只读测试 Vault，生成并重新读取 Vault 外恢复文件，将密文写入本地不可信 ObjectStore，结束源进程后在新建空目录恢复，并由独立验证器证明受支持文件的相对路径与字节完全一致。模拟服务器不得出现原始正文、文件名、扩展名、相对路径或裸内容哈希。

P0 不涉及真实账号、真实团队、生产服务器、自动监听、增量同步或冲突协调。

## 3. 资产

| 资产 | P0 中的形式 | 暴露后果 |
|---|---|---|
| Vault 明文（Markdown、附件、Canvas） | 用户磁盘上只读源目录 | 本地明文已在用户设备；P0 的职责是不让它泄漏到 ObjectStore 或日志 |
| 恢复文件 | Vault 外高熵秘密文件 | 失窃等价于获得域解密能力 |
| Recovery Root / bearer 恢复材料 | 持久化在 Vault 外恢复文件中，不进入 ObjectStore | 文件失窃等价于获得域恢复能力；当前不承诺独立静态保密保护 |
| 域数据根 | 从 Recovery Root 派生，仅在进程内存使用 | 暴露后可派生 Manifest/Object Wrap Key；P0 不承诺抗内存转储 |
| Manifest Key / Object Wrap Key | 从域数据根按独立用途标签派生，仅在进程内存使用 | 复用或标签碰撞会破坏用途隔离 |
| 对象密钥 | 每对象随机产生，解包后仅在进程内存使用 | 复用导致相同明文更易关联；P0 不承诺抗内存转储 |
| 对象 ID | 随机不透明标识 | 若用裸内容哈希则泄漏内容关系 |
| 密文对象 | ObjectStore 中的不可变字节 | 被篡改后恢复验证应失败 |

## 4. 攻击者

### 4.1 诚实但好奇的 ObjectStore

- 可以观察对象 ID、对象数量、密文大小、总密文字节、上传下载时间、协议版本；
- 不能解密正文、文件名、扩展名或相对路径；
- P0 不做大小填充或流量隐藏，在关闭报告中记录该限制。

### 4.2 被动网络观察者（阶段 7 以后）

- 只观察 localhost HTTP 上的密文对象；
- P0 阶段 7 限定 localhost，不涉及公网或中间人。

### 4.3 篡改 ObjectStore 内容

- 替换、截断、删除 Manifest 引用的密文对象，或在某个对象 ID 下返回不同字节；
- 上述情况必须通过对象 ID/AAD 绑定、AEAD 认证或缺失引用检查失败关闭；
- 对同一对象 ID 返回完全相同的不可变密文字节是幂等读取，不属于攻击，也不应被误报为重放；
- 用一套完整、合法的旧恢复文件和旧 ObjectStore 副本替换当前整套输入属于完整快照回滚。P0 当前没有外部新鲜度锚点，不能检测这种整体替换，也不承诺证明输入快照是历史上的最新状态。

### 4.4 持有过期恢复文件的实体

- 旧恢复材料可能解开其过去对应的旧副本；
- P0 只验证给定不可变快照的恢复，不涉及全域换代，也不提供完整快照反回滚保证。

### 4.5 P0 明确不防御的攻击者

- 已被恶意软件控制的授权终端（README §5.3）；
- 物理获取运行中进程内存的攻击者（侧信道、内存转储）；
- 通过恶意客户端更新进行的供应链攻击（除非完成可验证构建和独立审计）。

## 5. 信任边界

```text
可信域:
  源 Vault 目录（只读）
  恢复文件（Vault 外，高熵）
  进程内存中的域数据根和派生/解包密钥
  独立验证器进程（Python）

      ↓ 加密

不可信域:
  Directory ObjectStore（密文对象）
  ObjectStore 日志和访问记录
  密文 Manifest 对象的外部对象 ID、密文字节和已冻结的最小公开 header
```

恢复文件位于 Vault 外，但属于可信域：它足以恢复域，是高敏感秘密。完整 canonical Manifest 的路径、对象引用、大小、内容策略版本和包装材料都必须加密并认证；ObjectStore 即使完全被攻击者控制，也只能看到密文和已明确允许的不透明元数据。

## 6. 攻击面与缓解措施

| 攻击 | 缓解措施 | 验证方式 |
|---|---|---|
| ObjectStore 读取到明文 | 正文、文件名、扩展名、相对路径在离开设备前加密；对象 ID 随机不透明 | 服务器可见性扫描 |
| 相同明文产生可关联密文 | 每对象独立随机密钥和 nonce | 确定性测试：重复明文不应产生可直接关联的密文对象 |
| 对象篡改 | AEAD 认证；恢复验证逐文件核对字节 | 篡改、截断和缺失对象测试 |
| 完整旧快照替换 | P0 没有外部新鲜度锚点，不能从一套自洽旧输入证明其不是最新状态 | 明确记录为 P0 不提供的保证；不得把 AEAD 完整性写成反回滚证据 |
| 路径逃逸 | 拒绝 Symlink/Junction；路径必须保持在根目录内；恢复不允许写出目标根目录 | 路径逃逸和重解析点测试 |
| 非空目标覆盖 | 恢复器拒绝非空目标目录 | 非空目标测试 |

## 7. P0 安全边界声明（诚实边界）

P0 的端到端加密不能保护以下情况（README §5.3）：

- 已被恶意软件控制的授权终端；
- 合法用户主动复制、截图或外传的内容；
- 已经下载到设备的历史副本；
- 通过恶意客户端更新进行的供应链攻击（除非完成可验证构建和独立审计）。
- 用一套合法旧恢复文件和配套旧 ObjectStore 完整替换当前输入的快照回滚；P0 只能验证给定快照内部的认证与完整性，不能证明其最新性。

P0 关闭报告不得宣称已经实现零知识安全或已合规。这些声明需要独立审计证据，不属于 P0 范围。
